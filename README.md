
# DeepSeek Telegram Bot

Этот бот для Telegram использует **DeepSeek API** для обработки пользовательских запросов, поддерживает **хранение истории в PostgreSQL** и **Rate Limiting через Redis**.

---

## **📌 1. Установка зависимостей**
Перед запуском убедитесь, что у вас установлен **Docker** и **Docker Compose**.

Проверить установку можно командами:
```bash
docker -v
docker-compose -v
```

---

## **📌 2. Настройка переменных окружения**
Создайте файл `.env` в корневой папке проекта и добавьте в него переменные:

```ini
BOT_TOKEN=

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://openrouter.ai/api/v1

POSTGRES_HOST=
POSTGRES_PORT=
POSTGRES_PORT_OUT=
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=

REDIS_HOST=
REDIS_PORT=
REDIS_PORT_OUT=
```

## **📌 3. Запуск проекта**
🔹 **Запускаем весь проект (бот, БД, Redis) одной командой:**
```bash
docker-compose up --build -d
```

🔹 **Проверяем логи бота:**
```bash
docker logs deepseek_bot -f
```
---

## **📌 4. Проверка работы**
🔹 **Убедитесь, что все контейнеры работают:**
```bash
docker ps
```
🔹 **Зайти в контейнер PostgreSQL и проверить данные:**
```bash
docker exec -it deepseek_postgres psql -U user -d deepseek
```
🔹 **Проверить, есть ли лимиты в Redis:**
```bash
docker exec -it deepseek_redis redis-cli
keys *
```
Если есть ключи `rate_limit:<user_id>`, значит **Rate Limiting работает**.

---

## **📌 5. Использование бота**
🔹 **После запуска можно взаимодействовать с ботом в Telegram:**  
1. **Отправьте текстовое сообщение** – бот обработает его через DeepSeek.  
2. **Команда `/history`** – бот покажет последние 3 запроса.  
3. **Rate Limiting:** Если отправлять слишком часто – **бот ограничит запросы** (Redis сбрасывает счетчик каждую минуту).  

---

## **🚀 Query Enhancement - Интеллектуальное улучшение запросов**

### **💼 Бизнес-преимущества**
- **Повышение качества ответов** - AI понимает запросы точнее
- **Снижение повторных запросов** - экономия на API вызовах
- **Улучшение UX** - пользователи получают нужные ответы с первого раза
- **Конкурентное преимущество** - уникальная фича среди Telegram AI-ботов

### **🔧 Техническая реализация**

#### **1. `enhance_query(original_query, user_context="")`**
**Назначение:** Улучшает пользовательский запрос через DeepSeek API

**Детальный flow улучшения запроса:**

**Этап 1: Подготовка данных**
```python
# 1. Получение пресета для Query Optimizer
enhancement_preset = get_enhancement_preset()

# 2. Формирование промпта с контекстом
enhancement_prompt = f"""
{enhancement_preset}

Исходный запрос пользователя: "{original_query}"

{f"Контекст пользователя: {user_context}" if user_context else ""}

Проанализируй запрос и улучши его, если это необходимо. Верни только улучшенный запрос без дополнительных объяснений.
"""
```

**Этап 2: API вызов к DeepSeek**
```python
completion = client.chat.completions.create(
    model="deepseek/deepseek-chat",           # Консистентная модель
    messages=[{"role": "user", "content": enhancement_prompt}],
    temperature=0.3,                         # Низкая для стабильности
    max_tokens=500,                          # Ограничение длины ответа
)
```

**Этап 3: Обработка ответа**
```python
enhanced_query = completion.choices[0].message.content.strip()

# Валидация результата
if enhanced_query and len(enhanced_query) <= 1000:
    return enhanced_query  # Успешное улучшение
else:
    return original_query  # Fallback на оригинал
```

**Этап 4: Обработка ошибок**
```python
try:
    # API вызов
except (OpenAIError, Exception) as e:
    logging.error(f"Query enhancement failed: {e}")
    return original_query  # Fallback при ошибке
```

**Технические параметры:**
- **Температура:** `0.3` (низкая для стабильных результатов)
- **Максимум токенов:** `500` (ограничение длины улучшенного запроса)
- **Модель:** `deepseek/deepseek-chat` (консистентность с основными запросами)
- **Валидация:** проверка длины (максимум 1000 символов)

**Логирование процесса:**
```python
logging.info(f"Enhancing query: '{original_query}'")
logging.info(f"Query enhanced successfully: '{enhanced_query}'")
logging.warning(f"Enhanced query too long or empty, using original")
logging.error(f"Query enhancement failed: {e}")
```

**Бизнес-логика:**
- **Анализ намерений** → понимание, что хочет пользователь
- **Добавление контекста** → уточнение недостающих деталей
- **Структурирование** → переформулировка в оптимальный формат
- **Сохранение смысла** → не искажение оригинального запроса

**Примеры трансформации:**
```
"помоги с кодом" → "Помоги отладить код на Python, опиши возможные ошибки и предложи решения"
"как это сделать?" → "Как улучшить производительность веб-приложения на Django: оптимизация базы данных, кэширование, архитектурные решения"
"напиши стих" → "Напиши лирическое стихотворение на русском языке о весне, используя образы природы и философские размышления, 4 четверостишия"
```

#### **2. `should_enhance_query(query)`**
**Назначение:** Определяет, нуждается ли запрос в улучшении

**Детальный алгоритм анализа:**

**Этап 1: Анализ длины запроса**
```python
short_queries = len(query.strip()) < 10
# Критерий: запросы короче 10 символов считаются неясными
```

**Этап 2: Поиск расплывчатых слов**
```python
vague_words = [
    "помоги", "как", "что", "почему", "где", "когда", "кто", 
    "объясни", "расскажи", "покажи", "сделай", "напиши"
]
vague_queries = any(word in query.lower() for word in vague_words)
```

**Этап 3: Поиск неясных фраз**
```python
unclear_phrases = [
    "это", "то", "вот", "так", "как это", "что это", "помоги с"
]
unclear_queries = any(phrase in query.lower() for phrase in unclear_phrases)
```

**Этап 4: Принятие решения**
```python
needs_enhancement = short_queries OR vague_queries OR unclear_queries
```

**Логирование анализа:**
```python
logging.info(f"Query analysis - short: {short_queries}, vague: {vague_queries}, unclear: {unclear_queries}, needs enhancement: {needs_enhancement}")
```

**Критерии срабатывания:**

**✅ Запросы, нуждающиеся в улучшении:**
- **Короткие:** "помоги", "что?", "как?"
- **Расплывчатые:** "помоги с кодом", "как это сделать?"
- **Неясные:** "что это?", "как это?", "помоги с этим"

**❌ Запросы, НЕ нуждающиеся в улучшении:**
- **Конкретные:** "Напиши подробный анализ рынка криптовалют за 2024 год"
- **Детальные:** "Объясни принцип работы нейронных сетей с примерами кода на Python"
- **Специфичные:** "Создай REST API на FastAPI с аутентификацией JWT"

**Бизнес-логика:**
- **Экономия ресурсов** → улучшение только проблемных запросов
- **Повышение точности** → точное определение неясных запросов
- **Мониторинг качества** → логирование для анализа эффективности

#### **3. `get_query_analysis(query)`**
**Назначение:** Анализирует запрос и возвращает детальные метаданные

**Детальный анализ запроса:**

**Этап 1: Базовые метрики**
```python
analysis = {
    "length": len(query),                    # Общая длина запроса
    "is_short": len(query.strip()) < 10,     # Флаг короткого запроса
}
```

**Этап 2: Анализ вопросительных слов**
```python
question_words = ["что", "как", "почему", "где", "когда", "кто", "зачем"]
"has_question_words": any(word in query.lower() for word in question_words)
```

**Этап 3: Анализ неясных терминов**
```python
vague_terms = ["это", "то", "вот", "так", "помоги", "сделай"]
"has_vague_terms": any(term in query.lower() for term in vague_terms)
```

**Этап 4: Итоговое решение**
```python
"needs_enhancement": await should_enhance_query(query)
```

**Возвращаемые метаданные:**
```python
{
    "length": 15,                    # Длина запроса в символах
    "is_short": False,               # Короче 10 символов?
    "has_question_words": True,       # Содержит вопросительные слова?
    "has_vague_terms": True,          # Содержит неясные термины?
    "needs_enhancement": True         # Нуждается ли в улучшении?
}
```

**Применение метаданных:**

**📊 Аналитика качества:**
- **Статистика запросов** → процент коротких/неясных запросов
- **Тренды пользователей** → как меняется качество запросов
- **Эффективность алгоритма** → насколько точно определяется необходимость улучшения

**🧪 A/B тестирование:**
- **Сравнение версий** → эффективность разных алгоритмов анализа
- **Оптимизация критериев** → настройка пороговых значений
- **Измерение улучшений** → до/после внедрения Query Enhancement

**🎯 Персонализация:**
- **Адаптация под пользователя** → индивидуальные настройки анализа
- **Обучение на истории** → улучшение алгоритма для конкретного пользователя
- **Контекстные улучшения** → учет предыдущих запросов

**📈 Метрики для оптимизации:**
- **Точность определения** → процент правильно классифицированных запросов
- **Ложные срабатывания** → запросы, улучшенные без необходимости
- **Пропуски** → запросы, которые нужно было улучшить, но не были
